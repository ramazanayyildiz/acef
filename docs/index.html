A workflow and safety layer for AI coding agents

Make the change. Keep it true to the project.

ACEF helps an AI agent change an existing software project without ignoring how that project already works. You describe the result you want. ACEF studies the repository, chooses only the process the work needs, makes the change, and verifies the real result.

See how to start Understand the model
Why it exists

AI agents are fast. Software work is not always simple.

An agent can write plausible code quickly and still miss the project’s conventions, test the wrong thing, repeat reviews forever, or use a heavyweight process for a tiny fix. ACEF keeps the useful speed and adds structure only where it earns its cost.

Small work stays small

A contained, reversible change uses the project’s normal workflow. It does not open a full ACEF lifecycle.

Risk gets stronger checks

Security, payments, migrations, realtime, concurrency, and other high-risk work receive added safeguards and independent review.

The whole idea

Three things happen between your request and “done”

1

Understand

ACEF learns the project’s structure, commands, tests, and proven code patterns.

2

Choose

It selects a lightweight or rigorous path based on the scope and risk of this specific task.

3

Build and prove

The agent makes the change and verifies it where a user or another system actually uses it.

How to use it

Describe the outcome in plain language

You do not need to choose a workflow, a review policy, or an internal framework. Start with the work and any constraint you already know.

YouThe avatar disappears after a user edits their profile. Find the cause and fix it.
ACEFI’ll reproduce the behavior, find the root cause, make the smallest project-native fix, and run the focused regression test.
YouAdd team billing. Before implementation, tell me the scope and risk.
ACEFThis touches money and multiple product surfaces, so it needs a clear plan and extra safeguards. I’ll map the user journey and split the work before code starts.

Using an agent that has the ACEF skill installed? Address ACEF in the same way you normally ask that agent to work in a repository.

What to remember

Four promises, without the internal machinery

Use the project’s own patterns

ACEF follows proven examples already present in the repository instead of inventing a parallel architecture.

Use only the process needed

A tiny repair and a payment-state redesign should not pay the same planning and review cost.

Prove the real result

Code is not considered complete merely because it looks correct or an isolated helper test is green.

Stop unproductive loops

If repeated reviews and retries stop producing product progress, ACEF consolidates the findings, splits the scope, or asks for a decision.
