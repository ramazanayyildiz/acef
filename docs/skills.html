Capability catalog

Skills are tools inside the workflow—not workflows themselves.

You normally enter through the ACEF skill and describe an outcome. ACEF invokes a specialist skill only when its output is needed, then carries that output forward instead of recreating it.

The mental model

Workflow controls the journey. Skills perform bounded jobs.

1Your request

“Plan team billing,” “fix this bug,” or “build a regression pack.”

→
2ACEF routes it

Chooses project-native, Fix, Standard, or Full plus normal or extra safeguards.

→
3Skills do the work

Mapping, readiness, planning, review, testing, or release—only as needed.

→
4Evidence continues

Each output becomes the next skill’s input; the lifecycle does not restart.

Do not run the whole catalog. A skill is selected because the current task needs its artifact. Using every skill would add cost without adding confidence.
Single front door

Core orchestration

Everyoneacef

Coordinate the complete request

Use for ACEF-managed work. It reads the task, selects the workflow and safeguards, invokes only the required helper skills, and keeps the response lean.

Give it
Outcome, repository, constraints, and known risk.
Get back
Route decision, coordinated artifacts, evidence, verdict, and next step.
Internal routingacef-router

Classify an unclear request

Separates request type from execution workflow and identifies missing inputs before side effects begin.

Give it
A request plus available project context.
Get back
Route, minimum inputs, next artifact, and adapter need.
Product and planning

Turn intent into ready, coherent work

These skills clarify what should be built. They do not all run for every feature.

PM · Productstorymap

Map the user journey and delivery slices

Use for a new product, epic, or feature—or to extract user activities from an existing codebase.

Give it
Product idea or repository evidence.
Get back
Users, activities, tasks, journeys, priorities, and release slices.
PM · Productspec-readiness

Decide whether a brief is ready

Use when intent, persona, scope, data ownership, acceptance, or risk may still be ambiguous.

Give it
Feature request, brief, or story.
Get back
A file-backed readiness verdict, blocking questions, and risk flags.
PM · Architectureacef-specify

Prepare planning-heavy requirements

Uses existing BMAD, Kiro, or manual artifacts when available; otherwise guides requirements, design, and story planning once.

Give it
Approved brief, repository context, and existing artifacts.
Get back
Traceable requirements, design decisions, and coherent stories or tasks.
Repository and delivery

Ground implementation and review in project evidence

Developer · Read-onlyacef-adapter

Build ACEF’s living repository memory

Captures stack, commands, architecture, proven patterns, risk surfaces, and freshness. Reuse it until the repository changes materially.

Give it
Repository path.
Get back
Project adapter with snapshot and living pattern knowledge.
Developer · Discoverymap-codebase

Generate a code-grounded map

Scans stack, architecture, conventions, and concerns. ACEF can use this as the generic scan engine beneath its project adapter.

Give it
Repository or module path.
Get back
Codebase map and pattern registry.
Reviewer · Report onlybug-hunter

Find concrete behavioral defects

Reviews an explicit diff or bounded paths. It reports evidence-backed defects but never edits or approves a gate.

Give it
Bounded diff, criteria, context, and scan budget.
Get back
File, line, severity, impact, confidence, and evidence.
Reviewer · Report onlyimplementation-shape-review

Find simplification opportunities

Identifies repeated logic, heavy first-pass design, and project-shape mismatches without changing code.

Give it
Bounded change, acceptance, patterns, and evidence.
Get back
Prioritized implementation-shape candidates.
Release owneracef-release-adapter

Prepare release and rollback evidence

Reads the repository’s actual delivery setup and distinguishes deploy actions from real quality gates.

Give it
Change, target environment, risk, and project adapter.
Get back
Release readiness checklist, deploy path, approvals, and rollback path.
Testing and QA

Move from behavior to prioritized, executable evidence

Pick the entry point that matches your situation. Planning skills do not write test code; generator skills do.

QA · Front doortest-strategy

Choose the testing path

Starts from one of three situations: no test suite, a coverage gap, or a new feature.

Give it
Scenario, target, current testing state, and constraints.
Get back
Recommended test levels, boundaries, and skill sequence.
QA · Journeytest-user-flow-mapper

Deepen critical user flows

Maps ordered paths, actors, alternate states, error paths, and touched components before technical case planning.

Give it
Story map, routes, screens, source, or feature description.
Get back
Prioritized flow map.
QA · Documentationflow-document-composer

Document a flow end to end

Bridges discovery and test planning with a durable journey document readable by people and downstream skills.

Give it
Story map or flow map plus source evidence.
Get back
Technically anchored flow document.
QA · Planningtest-case-planner

Plan cases without writing code

Covers unit, integration, data, validation, async, browser, user-flow, and manual cases in priority order.

Give it
Story map, flow map, flow document, feature, module, or source.
Get back
Human-readable prioritized test plan.
QA · Analysistest-risk-classifier

Turn code risk into generation guidance

Enumerates branches, side effects, dependencies, complexity, and preconditions before tests are generated.

Give it
Test plan plus target class or module.
Get back
Structured risk profile.
Developer · Automationtest-generator

Generate unit and integration test code

Uses the risk profile and project framework patterns. Simple low-risk targets may use its bounded fast path.

Give it
Risk profile or eligible simple target.
Get back
Production-ready test classes and verification.
QA · Browser automationtest-browser-generator

Generate browser and end-to-end tests

Targets UI interactions and real user journeys using the repository’s Dusk or Playwright setup.

Give it
Browser cases, risk profile, or described UI flow.
Get back
Executable browser test code and verification.
QA · Existing suitetest-coverage-auditor

Find the highest-value coverage gaps

Quick Scan finds broad omissions; Deep Audit examines a bounded module method by method.

Give it
Source and existing test suite.
Get back
Prioritized coverage-gap report.
QA · Deliverableflow-suite-composer

Compose an executable regression pack

Assembles reviewed flow evidence and planned cases into a human-executable suite with automation targets.

Give it
Flow document, test plan, and optional risk classification.
Get back
Deliverable-grade flow test suite.
Repository setupacef-test-bootstrap

Establish the first accepted test pattern

Uses an existing framework when present. If none exists, it proposes options before adding dependencies.

Give it
Repository, target, test type, and framework status.
Get back
One small approved test pattern—not broad coverage.
Convenience commandtest-gen

Request coverage-driven generation directly

A compact entry point for “write tests” requests. It plans before generating and follows existing test conventions.

Give it
File or module target.
Get back
Test plan, generated tests, and coverage-oriented iteration.
How outputs connect

Common skill pipelines

Arrows mean “the previous artifact becomes input.” A pipeline stops as soon as the requested deliverable is complete.

Product discovery

storymap→spec-readiness→acef-specify→approved delivery units

New feature testing

test-strategy→test-user-flow-mapper→test-case-planner→test-risk-classifier→test-generator or test-browser-generator

QA regression pack

storymap or flow map →flow-document-composer→test-case-planner→flow-suite-composer

Coverage repair

test-coverage-auditor→test-risk-classifier→test-generator

Repository onboarding

map-codebase→acef-adapter→reusable project context for later work

Why some skills appear to overlap

map-codebase is the generic scanner; acef-adapter turns repository evidence into ACEF’s durable project memory. test-gen is a convenience entry point; test-generator is the structured generator used after risk classification. The orchestrator should choose one path and reuse outputs rather than invoking both as duplicate phases.

Where the exact skill instructions live

The repository’s skills/ directory is the exact source. Each SKILL.md defines triggers, inputs, procedure, output contract, and boundaries. This page is the human-readable catalog; the files remain the executable instructions.
